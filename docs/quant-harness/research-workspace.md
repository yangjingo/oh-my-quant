# Web 研究工作台：首个真实 Agent 任务

本入口实现一个窄任务：对明确的沪深主板股票做历史日线结构观察，与指定大盘基准比较，保存本次证据与判断，再独立取证复核。它是本地实验入口，不取代现有 TUI，不复用三方案静态原型代码。

## 产品定位与 Desktop-first 规划过渡（Refs #20 / #22 / #26）

依据产品方向与架构规划，本工作台代码位于应用侧（`src/app/research-workspace/`），与负责公共展示、文档和公开 Demo 的在线网站（`site/`）严格分开。体系划分三个层次：

1. **在线网站（`site/`）**：负责产品介绍、文档、博客与公开静态原型（如 #24），独立构建与部署；不承载真实研究工作台和本地数据服务。
2. **应用侧本地浏览器入口（当前）**：即本工作台（`src/app/research-workspace/web/` 配合本地回环服务）。它是单任务真实 Agent 研究链（取证、计算、引用、不可变快照与复核）的阶段性验证入口；采用原生 Web 界面技术不改变其应用归属，也不意味着转向纯 Web/云端产品。
3. **正式 JQ 桌面产品（未来规划）**：按 [#20](https://github.com/yangjingo/oh-my-quant/issues/20) 与 [#22](https://github.com/yangjingo/oh-my-quant/pull/22) 方案，正式 JQ 桌面 UI 将由 `apps/desktop` 的 renderer 承接，坚持 **Desktop-first 与 CLI 共存** 的演进方向。`apps/desktop` 尚属演进计划，当前本地 Web 路径不因此自动成为最终架构。

**未来 Desktop 接入的职责边界与契约约束：**
- **复用服务契约**：桌面端接入时复用本模块已跑通的单任务研究宿主、Source 数据契约、确定性计算和 Storage 不可变版本规范。
- **职责严格隔离**：桌面宿主负责系统窗口与本地能力，前端 renderer 负责界面交互呈现，领域计算与存储由对应服务承担；**禁止**在 Desktop 中复制一套独立的研究与计算逻辑，也**禁止**将服务端代码直接并入 renderer。具体进程边界与 IPC 协议遵循 #22 后续验证结论。
- **交付与验证区分**：交付记录严格区分「本地 Web 研究链通过」与「Desktop 实际运行/打包通过」，本工作台的验证通过不代表 Desktop 改造完成；网站构建与产品本地启动保持互不依赖。

## 运行

先按[产品配置](./configuration.md)配置可用模型，并安装 Python、AKShare、pandas。在仓库根目录运行：

```powershell
bun install --frozen-lockfile
# 使用已有 Python 环境时，为当前终端指定解释器：
$env:WHYJ_PYTHON = 'C:\path\to\python.exe'
bun run workspace:dev
```

打开 <http://127.0.0.1:4175/>。模型连接复用本地配置，密钥不会进入浏览器或本页的 API。服务只绑定回环地址，校验 Host、Origin 和变更请求令牌；没有远程访问、多用户登录或桌面安装功能。

首个研究样例：股票 `002048.SZ`，基准 `000300.SH`，起始日选择当年年初；问题为“最近回撤结构如何？相对大盘表现如何？哪些证据支持继续观察，哪些变化会破坏结构？”明确代码与日期是当前输入契约，不具备任意证券名称识别能力。

## 调用与责任

```text
Web 提问 /api/runs
  → 单任务宿主（范围、时限、取消、状态）
  → 现有 createLocalAgent / Pi 模型工具循环
      → get_market_evidence → Source 固定 Python → 股票、基准、交易日历
      → calculate_research → 纯计算 → E3，输入关联 E1/E2
      → publish_research → 引用与流程检查 → 模型解释
  → SSE 安全进度、结论 / 图表 / 证据 / 复核
  → 用户保存 → Storage 不可覆盖的版本快照
  → 独立复核 → 新取证、新会话、新版本，关联旧版本
```

宿主仅暴露上述工具和 `ask_user` 澄清工具，无 shell、任意 Python、交易或私有账户工具。12 次工具调用、每轮 240 秒、同一服务一次运行一个任务；单次服务最多保留 50 个运行记录。保留现有模型的推理配置，不默认降低深度。首个研究任务不会把模型最终一段自由文本直接当作完成结果，必须发布结构化研究；已有研究后的解释型对话另行标识。

通用 JSONL 仍记录实际 Agent 会话。Web 运行进度只在内存中，刷新页面可以接回当前任务；服务重启后只能打开已保存的完成版本，未保存进度不提供跨进程恢复。显式保存的研究制品位于 `.ohquant/research/workspace/<id>.json`（遵循 `OHQUANT_DIR`）；它不是另一份可写会话状态机。每个版本包括问题、范围、原始日线、来源、获取时间、输入哈希、计算结果、引用和模型解释，SHA-256 检测快照变化，但不是来源真实性认证。重复保存同内容幂等，改写同 ID 或校验失败时拒绝覆盖。

## 可核验的范围

- Source 调用 AKShare 的 Tencent 历史日线和 Sina 交易日历。股票为前复权价格，基准为指数点位。该接口名为 `amount` 的字段映射为成交量，不冒充成交额，成交额保留空值。
- 保守排除上海日期的当天日线，即使已经收盘也不纳入；展示实际覆盖日期。缺失日线不补造、不中途降级到合成数据。日历来自数据服务，不声称交易所终态认证。
- 指标：首尾收盘简单收益、收盘序列复利最大回撤、20/60/120 条均线；最新成交量 / 此前 20 条成交量中位数；最新收盘在当日高低区间的位置；股票与基准共同日期首尾收益之差（百分点）。均线不足返回空，不把空值当零。
- 近 20 条日线最低价只是观察边界，不声称支撑成立。相对收益是同区间收益差，不是回归 Alpha 或行业相对强度。未接入板块、基本面和成交额证据，不认证买点。
- 发布只检查必需计算和引用 ID 存在，并附加程序规定的缺口；**没有独立模型裁判或完整逐句数值/语义核验**。模型仍可能解释错误，必须查看原始证据。不能把“引用存在”显示成“研究正确”。
- 首次研究没有历史版本，空修订列表不意味着历史未修订。复核保留原起始日、标的和基准，结束日不倒退。比较共同历史的 OHLCV 修订，保存旧边界；覆盖不全、复权口径不一致、历史已修订或日期未推进时，不能把旧价格跌破发布为“失效”。新旧截止日相同必须明确报告，不能制造进展。

## 用户操作与验收

研究过程可停止（按钮或 Ctrl+G），中断模型与数据请求。已经取得的证据保留在本轮内；主动继续使用同一会话和原固定区间，不悄悄扩展成“最新行情”。重新取证用复核；跨服务重启恢复未完成任务暂不支持。关闭 SSE 或浏览器不会自动停止后台研究。

结论传递判断与条件；图表展示真实历史序列和计算；证据提供来源、覆盖与原始数据；复核呈现版本关联、原边界和修订。单纯保存不会重新请求模型。失败、取消或待澄清的运行不能保存；首个研究缺少发布结果也不能保存为完成研究。已有已发布研究后的普通解释可以作为对话保存，不冒充新研究结论。

### 连续对话（2026-10-16）

左侧为可滚动的完整对话，底部输入框保持可见；Enter 发送，Shift+Enter 换行，中文输入法组合输入不会触发发送。Agent 运行时可写下一条草稿，但不能同时提交第二个任务。右侧保持研究面板；窄屏通过“研究面板 / 回到对话”切换，避免输入框被长报告挤出屏幕。

`POST /api/runs/:id/followup` 在本次服务内沿用同一个 Agent 实例，因此保留真实模型/工具上下文。每轮拥有新的 run ID、回复、进度与保存状态，`conversationId` 关联同一对话；范围与证据不自动改变。澄清后的用户回复也走这一入口。已取消或失败的轮次先用“继续未完成工作”恢复。旧轮次的取消请求不能停止当前追问。保存后续轮次不改写早先保存的文件。

保存版本包含该轮以前的可见对话（问题、结构化回复、澄清和进度）及固定证据。历史消息的引用按钮查看其对应轮次的解释，共享本会话的固定证据；独立复核创建新的对话、重新取证，并继续关联原研究版本。每个对话最多 13 轮；当前不支持对话中途换股、改区间或分支编辑。

重启后没有内存中的 Agent 实例，会根据已保存的对话与证据创建新实例，界面明确显示“从已保存对话重建上下文”。这不是重放隐藏推理、逐字恢复完整 JSONL 或自动刷新行情；未保存的后续消息仍不承诺跨进程恢复。过长的保存上下文会拒绝继续，需新建对话。旧版单轮文件无需改写即可打开和追问。

自动化回归通过真实 Pi 循环检查：后续请求确实包含先前问题和回复、同一会话仅组装一次、来源没有重复读取、澄清能被回答、历史保存不被改写，以及重启后的上下文重建。

解释型追问允许直接的 assistant 文本，不强迫每个问题都重新发布研究。普通回复记在 `reply`，明确标为“对话解释”，不能产生新的 `answer` 或替代已验证计算；右侧继续显示最近一次已发布的研究。此类回复可以随对话保存，但已识别的未知 E 编号会阻止完成和保存。首个研究任务仍必须完成工具计算与结构化发布，只有自由文本的首次研究不能归档为完成结果。这里不提供逐句语义保证。

2026-10-16 实测保存的旧研究可继续为四轮对话：解释缩量、复述上一条问题、解释观察边界。最后一轮沿用同一个在内存中的 Agent，以普通文本约 7.5 秒完成，没有工具或来源刷新；全部证据与初次研究的哈希一致。保存后重新加载仍显示四轮。Enter、Shift+Enter、390×844 窄屏的面板切换和输入框可见性均做了浏览器检查。解释速度是该次样例测量，不是延迟保证。

自动化测试使用本机模拟模型服务，通过**真实 Pi 循环**调用工具，验证引用、计算、保存、重读、复核、取消、来源失败和本机 API 隔离，不调用公网模型。公网联调单独记录实际供应商、覆盖日期与耗时；不可把测试样本当作实际投资结论。

### 2026-10-15 实际联调记录

模型为本机已配置的 GLM-5.3，行情为上述 AKShare/Tencent 与 Sina 日历。首个股票/沪深300任务各返回 186 条日线，覆盖 2026-01-05 至 2026-10-14，研究完成耗时约 59.5 秒。独立复核约 50.5 秒，新旧截止日一致，明确报告未新增日线；两版本分别保存，重启服务后均能打开。

最终页面另跑一次真实任务：取证和计算完成后主动停止，3 份证据保留；继续后实际发布引用结论并保存。浏览器实测了开始、停止、继续、保存、图表、历史版本打开及独立复核。窄屏 DOM 检查没有横向溢出，但不据此声称所有移动设备适配完成。以上是单机样例，不是延迟 SLA，也不是模型语义准确率评测。

### 验收场景对照（Refs #26）

依据 Issue #26 对真实研究连续体验提出的 6 个关键验收建议，本实现对照与覆盖如下：

1. **首次配置缺项但输入保留**：当模型通过 `ask_user` 发起澄清时，运行进入 `needs_input` 状态，输入区与草稿完好保留供用户直接作答；若范围或格式校验失败，API 返回 400 并在底部显示错误，用户提问与表单参数原样保留不被清空。
2. **取数中停止再继续**：抓取行情或推理过程中可随时通过按钮或 `Ctrl+G` 停止（`/cancel`），已抓取的日线证据安全保留在内存中；随后可点击「继续未完成工作」（`/continue`）沿用会话与已有证据继续执行直至完成。
3. **成功保存后重启仍能打开同一证据**：研究完成后点击「保存本轮」写入本地不可变 JSON（含 SHA-256 校验）；服务重启后，页面可重新列出并打开历史版本，继续追问时从可见历史和固定证据中显式重建 Agent 上下文。
4. **没有新数据时复核明确「暂无新增」**：复核时若最新截止日与原版本相同（`advanced = false`），明确附加局限性说明「新旧证据截止日相同，覆盖日期尚未推进」，界面直接提示无新日线，不凭重新拉取捏造新进展。
5. **出现历史修订时能对照新旧值**：比对共同日期的 OHLCV，准确记录历史修订日期列表（`historicalRevisions`），保留原版本的观察边界（`previousBoundary`），并明确在口径或历史修订破坏可比性时，不把旧边界失效发布为跌破。
6. **数据失败时保留旧判断且明确本次未完成**：供应商取数失败或超时时，置状态为 `failed` 并展示脱敏错误信息；未完成的任务拒绝归档为完成研究（`/save` 返回 400）；复核失败不影响旧版本文件与判断。
