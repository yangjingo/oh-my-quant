# Workbench 会话连续性

状态：#105 分支实现，依赖 #102，尚未合入 main。完整任务恢复仍归 #77。

## 问题与目标

此前 Host 重启后丢失界面会话列表，浏览器刷新也会丢失选择和未发送草稿。研究者需要回到原对话继续提问，而不是重新说明上下文。

本阶段实现：同一工作区重启后保留会话身份、名称、已保存对话及工具记录；追问恢复原 Quant/Pi journal；浏览器恢复选择和草稿；意外中断明确标识，不自动重放模型或工具请求。

## 用户故事与优先级

| 优先级 | 场景 | 可观察结果 |
| --- | --- | --- |
| P0 | 服务升级、重启后回到研究 | 原会话仍可找到，追问引用旧上下文，不自动重复旧工具 |
| P0 | 刷新页面或重开窗口 | 恢复原选择与草稿，草稿不会自动发送 |
| P0 | 模型或工具执行中进程退出 | 显示“意外中断”；未知工具结果保持“待核对”，继续提问前明确确认 |
| P0 | 文件损坏、版本未知、并发修改 | 保留原始字节并解释问题，其他有效会话和新建仍可用 |
| P1 | 许多已结束研究 | 列表只读有界元数据，历史与 Agent 按需加载，结束后释放 Agent |

不自动导入其他入口的 journal、旧内存备份或凭证，不迁移不可变研究成果，不增加另一套 Agent 循环或事件数据库。恢复对话不等于恢复完整任务执行，更不等于独立核验结论。

## 格式与兼容性审查

沿用现有 Quant/Pi journal 作为模型上下文。新增 `.ohquant/workbench/sessions/{id}.json` 是界面检查点：记录稳定身份、名称、原工作目录、对应核心会话、可公开对话投影和运行状态。它补充流式部分内容、工具阶段及界面身份这些现有 journal 不直接提供的状态，不作为研究证据或工具副作用账本。

格式支持版本 1 和 2：第一行是有界 JSON 元数据与完整内容摘要，后续为快照 JSON。列表只读第一行；读取会话时再校验版本、摘要、工作区/会话/运行身份。中断以外的终态需要持久化核对状态时使用版本 2；旧版记录由新版读取时投影核对状态，读取不修改文件。版本 2 写入后不会自动降回版本 1。旧服务会拒绝版本 2 并保留原文件，旧服务对旧版记录本身没有新版保护，回退前需人工核对或继续使用新版读取器。通过现有原子替换、文件锁和存储 revision 拒绝过时写入；新旧完整文件二选一，不能先删除已提交文件。未知版本或损坏文件不自动转换、不覆盖、不隐藏。

新增格式在独立目录内，无现有文件转换。旧版本 Host 不认识这些记录，但回退也不得删除；原 settings、journal、不可变成果路径与格式不变。原工作目录保留在记录中，避免从另一检出目录启动时错误恢复其他上下文。缺失或不匹配的核心 journal 必须报错，不退回空上下文冒充追问成功。

## 生命周期与界面

提交前先持久化接受意图，无法保存时不开始模型请求。可见流式更新合并写检查点，工具执行前及结束/停止时完成保存。进程退出留下的 running 记录在读取时呈现为 interrupted；读取本身不发送模型请求、重写旧记录或把未知工具结果标成失败/成功。准备中的工具标为未执行，已经开始但未保存结果的工具标为待核对。

用户确认“我已核对，继续提问”只解除当前运行的提问限制，不执行原任务，也不把结果标成已验证。工具失败后的待核对状态可以伴随失败、完成或等待输入；新的问题才触发恢复原 journal 和执行，也不保证外部操作去重。取消或未完成研究不能由晚到事件复活。

Turn 可选的 thinking 字段保存模型返回的非隐藏文本安全投影，与回答分别保留；不保存签名或原始 provider payload。旧 v1 检查点没有该字段仍可读取，无格式迁移，也不自动补取历史思考。中断保留已提交检查点中的投影，取消时保存已收到的片段；重新打开不会请求模型续写。

浏览器按 workspace/session 保存选择和未发送草稿；只有已确认提交且内容未被用户继续编辑时才清除此草稿。存储不可用时保留当前窗口输入并提示，不能伪装保存成功。浏览器存储不是运行或历史真值。

## 验收与指标

用真实 Host 子进程和受控模型进行结束后重启、等待/执行中强制退出、恢复后追问、确认前禁止新请求等验收；核对请求/工具计数、稳定 ID 及原有文件摘要。补齐损坏、未知版本、过时写入及浏览器存储失败/会话隔离测试。

记录多会话列表、快照、重连字节量与资源释放行为；不以包体积代替延迟，不承诺未经同机实测的改善。原始输入与成果没有因资源优化而被删除。宽/窄屏及键盘操作分别实测，受控模型不证明真实模型质量。

未决事项：跨入口发现、未知副作用自动核对和完整任务恢复仍需 #75/#77；不在本阶段给出交付承诺。以本规范的确定性验收、完整发布检查和最终修订 CI 作为交付门槛。

评审修复：提交成功只清理本标签页未变的草稿，删除共享草稿前还核对当前持久化内容，保留其他标签页写入的新值。切换会话先准备目标快照，再同时提交选择、内容与草稿；读取失败保留原会话并标明目标错误。大历史用例将 30 个检查点的异步准备与 5 秒行为断言分开，清理等待种子写入结束，避免测试超时后删除仍在写入的目录；不修改生产 I/O 或验收断言。
