# 账户业绩：先分清投资变化与资金进出

账户余额增加，并不一定是投资赚了钱；余额减少，也不一定是策略亏损。若期间存在入金、提款或证券转入，仅凭期初和期末两个数字就可能得到完全错误的收益。

账户业绩因此拥有独立的只读历史接口。它消费用户授权的完整历史，交付有口径的收益与现金流解释，不借用观察组合假设，也不从当前持仓快照倒推交易历史。当前已有规范化文件与宿主接入路径，尚未接通并验收真实券商或 MCP 历史服务。

## 授权、规范化与计算分属三层

可信宿主决定读取哪个账户、什么区间以及结果向谁展示。历史适配器负责鉴权、来源识别、分页和币种转换，交付同一账户、同一报告币种的完整历史。计算层核对输入一致性并计算业绩，不发现账户、不读取凭证，也不执行订单。

接口需要的不只是数值，还包括来源引用、观察时间、区间边界与完整性声明。返回账户或窗口与请求不符时应拒绝，不能把“读到了一份合法账单”当成“读到了用户选择的账单”。

这样的拆分允许替换券商或文件格式，而不改动收益计算；代价是接入方必须先解决原始账单语义。标准化文件不是任意 CSV，声明完整也不自动证明来源真实。计算层能够识别内部矛盾，无法认证所有遗漏或错误分类。

## 为什么要在资金流处估值

当前方法使用时间加权收益：在每次外部资金流处分段，分别衡量投资增长，再连接各段结果。两端估值和资金流发生前的估值都需要明确，费用已计入权益时不能再次扣除。

一个简单例子是：账户从 100 增长到 110，随后投入 100，期末变成 231。余额增幅是 131%，但两段投资增长各为 10%，连接后为 21%；中间入金没有变成盈利。这个例子也说明，只有期初、期末和总入金额仍不足以还原每段表现。

GIPS 对外部现金流和时间加权收益的讨论提供方法背景。[1] 本项目选择需要资金流时点估值的严格输入，而不是在缺失时静默降级为近似算法；这提高了输入门槛，但使结果含义稳定。引用 GIPS 不表示当前输出符合整套标准。

时间加权收益也不回答所有问题。它侧重剥离外部资金时点的影响，不能代替投资者实际投入金额与日期下的体验。需要其他收益口径时，应明确建立对应方法，而不是复用同一个“收益率”字段。

## 最容易出错的是资金流分类

账户外部入金、提款与证券转入转出影响资金基数；账户内部买卖、留在账户内的股息利息以及已扣费用，不能全部归为外部资金流。证券转入也需要当时价值，不能仅记录数量。

同一时点可能有多笔流入与流出，既要保留独立事件身份，又要按一致时序参与估值。费用完整性与现金流完整性分别检查，未知不能按空列表处理。跨币种转换需要明确来源与币种，计算层不会临时抓一条汇率填空。

这些要求可能使一份看起来信息丰富的账单仍然无法计算。拒绝并不是输入检查过于苛刻，而是缺失信息确实改变了问题：不能一边没有资金流前估值，一边声称已经准确剥离了资金时点影响。

## 输出应保留方法可以看见的范围

结果交付净损益、时间加权收益、单位权益路径、已扣费用和可观察回撤，并附账户身份、期间与方法。净损益与收益率分别回答金额变化和资金效率，不能互相推导成不存在的交易明细。

回撤只能覆盖提供的估值点。如果只在少数资金流日期估值，路径中间的更深回撤可能看不见。净值归零、非有限结果或不满足方法的重新入金情形，也应明确失败，不能用零收益接续一条无法定义的曲线。

来源缺失、取消或读取失败时不切换账户、不退回公开行情，更不生成一份“空账户、零收益”的成功结果。当前只读接口没有下单、撤单或划转能力；具备读取权限也不构成交易授权。

## 私有输出不绕经研究模型

账户引用、权益和收益都属于私有数据。当前计算模块不把结果写入公开行情缓存或默认研究会话；可信宿主可将结果交给独立私有报告，显式文件导出由用户选择新位置。默认研究年报仍只描述观察组合，不自动加载账户历史。

这样会减少“让模型直接帮我总结所有账户”的便利，但避免默认研究上下文悄悄扩大为账户数据通道。若未来引入此能力，应另行明确授权、传输、保留和分享边界，而不是因为页面已有报告组件就自然接通。

年度私有报告目前严格使用 UTC 区间；券商按本地时区定义的年度需要接入方明确转换。现有合成账本验证只能支持计算与隔离边界，不能证明真实分页、资金分类或账单转换已经正确。

本页与[执行](./execution.md)共享账户身份概念，却不共享权限和数据充分性：交易接口的余额快照服务当前操作，历史业绩接口服务区间解释。让两者各自要求足够输入，比强行复用一个“账户对象”更容易保持含义清晰。
