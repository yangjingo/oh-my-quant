# 量化工具：让计算结果与解释各负其责

模型擅长把问题组织成研究过程，但一段流畅解释可能同时混淆单位、窗口、输入来源和收益口径。把计算交给工具能减少算术错误，却不能自动消除这些误读：工具算对了，模型仍可能把期间上涨比例说成交易胜率，把相对基准的差值说成 alpha。

内置工具因此承担两个任务：在明确假设下完成可重复计算，并交付足够清楚的结果语义。模型负责提出问题和解释条件，研究层核对输入与结果的对应关系；任何一层都不能替另一层宣布成功。

## 接口以研究问题划分，不以入口划分

数据工具获取观察，计算工具处理固定输入，研究服务连接来源、计算与归档，界面呈现结果。相同计算应被 Desktop、CLI/TUI 和报告复用，避免每个入口维护不同公式。

计算接口接收标的身份、研究窗口、方法与必要假设，交付指标、实际计算日期、输入引用及无法计算的原因。需要取数的工具由运行时绑定数据服务，纯计算不直接访问账户或修改配置。研究结果能够生成报告，不意味着计算工具拥有发布或交易权限。

当前 CLI 研究围绕一个活动观察组合进行，跨组合比较不在其活动工具集合中。独立比较服务与历史结果核验仍保留，详见[组合比较](./portfolio-comparison.md)。静态目录中有一个工具，不能据此推断当前入口已开放它。

## 因子名称不是完整的方法定义

“动量”“波动率”“量比”只有连同窗口和单位才有确定含义。当前六类因子包括动量、反转、波动率、量比、RSI 和均线偏离；它们提供研究观察，不直接输出买卖判断。

几个容易混淆的边界需要明确：因子波动率是未年化的期间离散度，风险工具另使用声明的年化口径；普通量比的均量包含当前观察，而严格价量研究中的前序量比排除当前观察；均线偏离比较两条均线，不是收盘价到均线的距离。反转因子只是动量取反，不能证明反转将发生。

预热样本也属于研究范围。若请求窗口不足，工具报告样本不足，不能偷偷引入窗口外数据使结果看起来可用。同一任务的多个因子应绑定相容的观察版本，否则六个正确数值也可能描述六个不同时间的问题。

Alpha101 给出了显式因子公式，是理解“方法必须能被确定表达”的参考；本仓库现有六类技术因子并不等于已经实现或验证 Alpha101 因子库。[1]

## 回测需要交付账本，而不只是分数

一条漂亮净值曲线不能解释收益如何形成。回测输出需要保留信号与成交时序、仓位、现金、费用和逐期权益，才能区分策略变化与模拟规则变化。

内置 SMA 回测使用前一根信号在下一根收盘成交，允许碎股，没有滑点、整手或涨跌停模型。独立的 [Alpha 引擎](./alpha-backtest.md) 采用另一套显式撮合假设。两个引擎都能给出收益率，不代表结果可以直接互换。

收益、风险与基准评分也不是同一种结论。CAGR 描述给定起止日期的增长；Sharpe 依赖收益期间与基准收益假设；历史 VaR/CVaR 描述样本尾部，不是未来损失上限。无有效分母时保留不可计算，而不是显示零。Sharpe 对时间跨度的依赖已有明确讨论，不能因为统一显示为年化值就忽略观察频率和序列性质。[2]

评分与历史 Dashboard 用于组织已有研究，不提供普遍投资排序。不同区间、币种和成本假设的记录不能靠一个总分消除差异；当前评分曲线没有自动完成跨币种换算。训练/测试划分也不足以证明免于反复挑选策略造成的过拟合，评测依据另见[量化评测](../evaluation/README.md)。

## 资金持续进入时，必须先问在衡量什么

基金定投中，累计投入增加会推高账户市值，即使投资表现没有改善。因此，利润相对投入的比例、剔除外部流影响的时间加权收益，以及考虑投入日期的 XIRR，应作为不同问题的答案呈现，不能互相补位。

当前定投模拟消费单位净值，按计划日之后的可用净值安排申购，允许碎份额。费用来自显式假设或当前公开费率；当前费率不是历史费率。未知费用采用零费假设时必须说明，无 XIRR 解也不能以本金收益率替代。

该模拟未完整处理现金分红、拆分、赎回费用及历史申购限制，因此既不是基金总回报认证，也不是实际账户业绩。真实账户需要另一套[历史与现金流接口](./performance.md)。这种拆分让“假设投入一笔钱会怎样”和“我的账户实际赚了多少”不会共用一个容易误导的结果标签。

## 用户给定材料，可以精确计算但不替它认证

显式加权评分和持仓情景只消费用户给定的数值、日期与假设，不自动查询行情或账户。评分工具计算每项贡献；情景工具计算给定价格变化下的市值和相对成本盈亏。

例如，某项原始分数最高，却可能因为权重较小而不是最大贡献项。再如，成本价 50、观察价 42，观察价上涨 10% 后仍低于成本。短例子的价值是暴露分母与权重的差别，不是提供市场预测。

这类工具应拒绝缺项与含糊单位，不自行归一化错误权重，也不把用户材料的日期升级为行情新鲜度。算术正确只支持条件结论，不能认证原始评分合理、账户真实或未来情景发生概率。

<a id="registry"></a>

## 工具可见、可调用与结果可信是三层边界

注册表统一提供能力说明与依赖，宿主决定活动工具，任务约束进一步收窄可调用范围。界面与模型消费同一能力信息，避免出现界面显示可用、实际会话却没有该工具的双重目录。

状态同样需要分层：无需联网只说明依赖少，安装成功只说明资源存在，端点样本通过只说明那次请求成立。真正完成研究还需检查原始参数、固定数据及结果。一个新工具被注册，不会自动获得研究验收资格；它必须有明确的结果核验方法。

<a id="numeric-stability"></a>
<a id="price-volume"></a>

数值稳定与证据完整也不能互相代替。计算层对极端数值、缺失观察和不可表示结果作明确处理，不能用零掩盖溢出。严格价量接口进一步要求已收盘、连续样本、单位和日历证据；当前内置来源尚不能默认满足全部证明。公式函数可以处理数组，不代表数组已适合该项研究。

最终，工具应把可确定的计算交给确定过程，把不确定性留在结果中。回答复核只覆盖明确绑定的部分数字与断言，仍不能理解任意金融叙述。报告只能据实际核验范围展示结论，不能用工具调用成功替代解释质量。
