# 报告与制品：固定结果，也固定它成立的条件

研究报告经常被当成对话结束后的导出按钮。但对长期量化观察而言，真正的问题发生在以后：行情更新了，模型回答变了，模板升级了，读者还能否知道当时的结论基于什么？

Artifact 的职责是把一次研究固定为可定位、可检查的版本。它接收经过整理的研究输入、结果与解释，交付报告和来源关系；不把生成页面等同于完成研究，也不替数据供应商或模型承担真实性保证。

## 报告里存在三种不同的内容

固定数据说明本次计算实际使用了哪些观察；已核验结果说明在给定参数和方法下能够独立重算；会话解释说明模型如何组织这些结果。三者可以同时存在，却不能使用同一个“已验证”标签。

例如，一份报告中的 RSI 可以与固定价格重算一致，但“因此即将反弹”仍是模型解释。完整工具轨迹只证明发生过哪些调用，不证明每句话都有充分依据。报告需要保留这种差别，避免专业排版放大本来有限的证据。

W3C PROV 将来源、处理过程与产物联系起来，提供理解这类关系的参考。[1] 本项目采用自身的会话和数据版本结构，没有实现整套 PROV 交换格式，也不把内容哈希当作外部认证。

## 为什么从会话派生，而不再建一份实时账本

会话已经保存用户输入、工具调用及结果；报告从所选分支派生轨迹，再连接固定数据。若另建一套持续更新的轨迹账本，就会出现两份状态在取消、恢复或分支切换时谁更权威的问题。

当前选择减少了同步真源，但要求派生过程准确识别分支、调用关系与计算窗口。摘要不能替原始工具事实，另一分支的成功也不能补成本分支的证据。报告消费已保存的研究，而不是以渲染阶段重新猜测研究过程。

自动生成默认关闭。启用后，也只在符合条件的研究轮次完整保存后生成；普通界面操作、中断请求或恢复会话不能被误认成新研究完成。生成失败应与研究本身的成功区分，避免因为报告没写出而重复执行已经完成的计算。

## 不可变版本保留的是什么

每份报告固定 HTML、元数据与来源绑定，恢复时核对原分支记录、顺序、父链和内容。来源可以继续追加新研究，但被引用的原记录如果变了，就不能静默接受。

旧报告用保存的页面字节打开，不按今天的行情或模板重画。这会让旧版保留过去的措辞与视觉形式，却使“我当时看到的是什么”有稳定答案。需要纠正时生成新版本或明确补充解释，而不是无声覆盖。

报告引用存在、页面仍可读取、原始数据还能重算，是三种不同状态。原数据被删除后，页面可能仍在，但验证资格应变化。系统不能用最新缓存替换旧输入，也不能因为页面好看、文件哈希正确就宣布整个研究仍然可验证。

## 恢复不是只有读文件成功

恢复服务接收固定报告版本，先检查来源，再准备目标会话和资源，成功后才切换活动状态。失败应保留当前工作，并说明是页面、来源还是资源不可用。

这里有一个刻意保留的成本：即使用户只想继续对话，严格恢复也可能因缺档案被阻止。原因是继续研究会让模型消费过去的结论；若无法确认这些结论的依据，把旧文字直接当成当前事实反而更危险。查看旧页面与恢复可继续研究的状态，不必拥有相同的成功条件。

任务要求报告时，还需核对报告是否包含最终接受的结果。较早的草稿不能因为引用了同一任务名称就替代最终交付。任务完成条件由[研究编排](./README.md#recovery)负责，Artifact 提供固定产物和可检查的来源。

## 分享需要重新选择内容

完整研究可能包含用户输入、私人组合名称和模型转录。先复制整份报告再尝试删除敏感词，很难发现所有间接泄漏；因此公开分享使用独立白名单投影，只选择允许的公开行情、来源、日期、经核对的无金额结果及匿名组合。

这意味着分享副本可能无法还原完整研究对话。它优化的是可公开讨论的结果，不是把所有内部材料原样交给别人。预览和下载使用同一版本内容，操作本身不上传；私有账户年报也不能接入这条公共分享路径。

完整报告部分图表依赖外部资源，并提供相应静态回退；分享副本使用内联样式、SVG 和原始数据呈现，以减少离线阅读依赖。能渲染不等于能复核，离线可读也不等于没有私密内容，这两项判断仍各有责任。

## 新增结果类型时，先定义证据边界

一种新计算能够画图之前，应先回答：参数如何绑定，原始输入从哪里读取，结果如何重算，哪些字段允许公开。否则图表支持越多，报告越可能把核验范围不同的内容混为一谈。

Artifact 不需要复制所有算法和接口细节。它只需要确认各生产方提供了足够的来源与方法，并在不支持、缺失或冲突时保留明确状态。年度叙事见[年度报告](./annual-reports.md)，账户历史见[账户业绩](./performance.md)，底层版本保留见[存储策略](../agent-runtime/storage.md#artifacts)。
