# Web UI 设计草案

更新：2026-10-25。范围：[#84](https://github.com/yangjingo/oh-my-quant/issues/84) 的设计交付，对应 [#81](https://github.com/yangjingo/oh-my-quant/pull/81) / [#50](https://github.com/yangjingo/oh-my-quant/issues/50) 的后续 React 实现输入。

本文整理维护者在 2026-10-24 至 2026-10-25 对 Web 原型确认的需求。下文的「原型已实现」仅指独立静态原型；不代表生产 Web、CLI/TUI、Host 或 Electron 已完成。生产技术选型仍是 React + TypeScript + Vite。原型代码位于 [prototypes/web-terminal](../../prototypes/web-terminal/README.md)，不进入 CLI 构建，不替换 #81。

## 与 PR #81 对照

这是待评审的 Web UI 草案，不是已经选定的替代实现。对照基线为 #81 的 `a5ac07d74a5d5195c9fecd8efa1f8733e32e2697`；两个分支均基于 main 独立评审，不互相覆盖。

| 比较项 | #81 React 工作台 | #84 Web UI 草案 |
|---|---|---|
| 交付角色 | `apps/web` 的 React + TypeScript + Vite shell 与客户端契约 | `prototypes/web-terminal` 的独立静态设计参考 |
| 会话区域 | 工作区切换、对话记录 | 默认收起的 Sessions、搜索/置顶/重命名、本页草稿保留 |
| 结果访问 | 右栏「概览 / 结论 / 证据 / 成果」四标签 | Overview 只保留紧凑行情；结论在回答中，证据/报告从回答打开 |
| 输入 | 单容器 textarea 与内部快捷键/发送带 | 单行提示符/输入/发送；键入 `/`、`@` 后全宽候选和目录导航 |
| 设置 | 模型设置与反馈弹窗 | 共用分区弹窗，底栏直达模型、数据源和运行状态 |
| 状态边界 | fixture client，订阅释放与取消分离的接口 | 本页模拟；运行时禁止切换，不能作为 Host 的最终语义 |

按相同窗口尺寸比较输入占用、对话阅读、结果是否容易找到和设置入口；不据静态截图判断性能或生产可用性。未来整合应保留 #81 的客户端契约及全部结果访问能力，再迁移经过确认的布局和组件。#81 的视觉证据以该 PR 的原始截图为准；本轮截图只验证本草案。

## 1. 基本原则与草案布局

Web 应体现 CLI/TUI 的连续研究体验：深色终端底色、等宽文本、少量金色强调、轻边框，优先呈现问题与回答。避免长期占用空间的多层工具栏、重复状态、卡片堆叠和所有内容同等高亮。

```text
┌ 品牌 / 版本 ─ 会话侧栏入口 ─────────── 新建 / 设置 / 概览 ┐
│ [Sessions] │ Session：问题 → 过程摘要 → 回答 │ Overview │
│ 默认收起   │ 各区域独立滚动                │ 观察组   │
│            │ 内容靠左，小边距              │ Market   │
├───────────────────────────────────────────────────────┤
│ › 继续提问 · / 命令 · @ 引用                    [↑ / ■] │
├ 模型（可点） · 数据源（可点） · 运行状态（可点） ──────┤
```

- 默认两列：会话 + Overview。Sessions 从页头展开，桌面展开后为三列。
- 同一 workspace 网格内，各面板顶边和底边对齐；不通过给每个子区块写固定高度实现。
- Composer 横跨工作区，输入与发送在同一行。底栏是独立的一行状态入口。
- 读内容的滚动容器是 `#stream`；Overview 和 Sessions 自己滚动，长内容不挤掉输入框。
- 右侧定位为行情概览，结论保留在回答中，证据与报告从对应回答进入。这个安排是对 #81 当前右侧四个标签页的设计调整，迁移时必须保留结果访问能力，不能只删掉原入口。


### 视觉约定

| 角色 | 设计值 / 规则 |
|---|---|
| 背景 | `#0C0C0C`，面板仅轻微层次差异 |
| 正文 | 暖灰 `#B8B4A8`，长段落不统一使用亮奶油色 |
| 次要信息 / 过程 | `#8F8A7B`，通过标题、缩进和间距同时区分角色 |
| 强调 | 奶油色 `#FFF3C4` 用于重点；金色 `#C99A2E` 用于提示符、选中和焦点 |
| 边框 | 低对比 `#302E27`，约 3–5px 小圆角 |
| 字体 | 原型本地 Geist Mono，中文系统回退；不采用大型营销标题与装饰字体 |
| 图标 | 复用已有品牌 SVG；动作采用本地 Lucide sprite，保留许可证 |
| 行情颜色 | 红涨、绿跌；不覆盖错误与运行状态语义 |

视觉意图与根 [DESIGN.md](../../DESIGN.md) 一致。原型版本以 `data/brand.js` 为展示真源，交付基线是根 package v1.4.0；未来更新时需同步核对根版本和原有品牌资产。

## 2. 页头 Header

- 左侧使用仓库已有 `logo-mark.svg`，并显示 WhyJ Quant 与 repo 版本，不另创品牌或保留旧的 `0.1.0`。
- `#projectSwitch` 显示当前标的 / 会话，点击切换 Sessions 侧栏；默认收起，`aria-expanded` 随状态变化。
- 新建、设置、概览按钮使用紧凑 Lucide 图标，保留 tooltip、可访问名称和键盘焦点。
- 窄屏减少次要标题信息，保留会话和设置入口；演示身份在内容、刷新提示与底栏仍然可见。

## 3. 左侧 Sessions

- 按会话组织：搜索、新建、日期分组、标题、更新时间、标的与状态；当前项用金色细边和轻底色表示。
- 置顶等次要操作在 hover/focus 时显示，触屏保留可见入口；不添加常驻「展开 / 收起 / 设置」文字占位。
- 支持搜索、置顶、重命名、新建、会话切换。会话标题本身可进入命名设置。
- 原型切换时保留本页生命周期内的消息、输入草稿、引用、撤销历史与阅读位置。刷新浏览器不会恢复这些会话数据。
- 原型运行中阻止切换并提示先停止，这是模拟器的限制。生产 #50 的共享运行要求是切换只取消订阅、不取消后台任务；必须改为 Host 管理，不得把原型限制复制成最终契约。


## 4. 中央 Session / Stream

- 参考 CLI 与 Codex/ZCode/DSH 极简会话：用户问题 → 一行可折叠过程摘要 → 最终回答。
- 不居中排版。桌面 `#stream` 水平内边距 16px，窄屏 10px；问题、过程与回答使用约 16px 的共同内容缩进。正文最大行宽仍受约束，避免超宽屏出现无法阅读的长行。
- 问题使用 `›` 提示符、保留换行；超过约 120px 的长问题可展开。回答旁的复制等次要操作弱化。
- 过程默认收起；展开后显示工具摘要、耗时和嵌套结果。过程色比回答弱，必须有显式过程标签和结构区分，不仅依靠颜色。原型展示的是合成操作摘要，不宣称提供模型隐藏推理。
- 图表按需展开；证据与研究报告从回答的入口打开，保留引用和版本访问。
- 发送期间箭头变为停止图标；停止后保留当前输入与已有演示记录。滚离底部时提供「回到最新」。
- 空会话显示简短引导和示例问题，不填入其他会话的行情或研究结果。


## 5. 右侧 Overview

参考 [#80](https://github.com/yangjingo/oh-my-quant/issues/80) 的信息减负要求：

- 每行只显示代码、名称、涨跌幅；代码弱化，百分比右对齐，保留红绿语义。
- 观察组与 Market 两组，标题/数量在一行；观察组支持键盘展开和收起。
- 顶部只有一条 `Refresh: YYYY-MM-DD HH:mm`。它是本地刷新事件，不是所有证券共有的交易日；开关面板不会更新该时间。
- 删除每行的日期、provider、fallback 文本和整个 Source 块。来源集中在底栏，底层记录仍保留元数据。
- 原型刷新时间为固定记录，显式标「示例」。无数据时为 `Refresh: — / 未刷新`。
- 组件接受 loading / partial / error / timeout 的简短提示，旧值不冒充新值；这几种状态只做了组件契约验证，未接入真实刷新或重试，不作为本轮浏览器网络验收。
- 点击底栏选择未连接的数据源后，Overview 不再显示合成行情。历史回答仍是清楚标识的旧示例。

## 6. Composer 与 `/`、`@`

最终输入区只保留提示符、文本输入、发送 / 停止：

- 删除 `.composer-meta` 下方说明带，将必要提示合并到输入区。
- 删除 `/`、`@` 两个 trigger 按钮，只用灰色占位文案「继续提问 · / 命令 · @ 引用」。键入仍触发对应候选。
- `#send` 使用 Lucide `arrow-up` / `square`，可访问名称分别为发送和停止。
- `/`、`@` 候选及目录二级结果与整个 Composer 外边缘完全同宽；不只对齐 textarea，不另设 300px 小弹窗。
- 菜单依次包含标题/范围、分类（仅引用）、可滚动候选、快捷键。弹窗向上展开，不挡住输入和发送。
- ↑/↓ 选择，Enter/Tab 确认，Esc 关闭；命令补全后再次 Enter 执行。Shift+Enter 换行。
- 候选检测以光标位置为准，替换当前 token，保留其后的文本；IME 组合输入不发送。系统中文 IME 仍需目标机器人工验收。
- `@` 支持示例文件、目录、历史会话，路径可含空格；引用身份与可见标签分离，支持整体删除和撤销。
- CLI 命令名来自项目语义；Web 专属动作单独标识。需要 Host 的命令保留草稿并说明未连接，不伪造执行成功。


参考的是交互机制，不承诺 ZCode/DSH 的全部功能等价。真实目录搜索、引用解析、权限、异步去重与失效控制、标准化引用编码必须由 Host 接入；示例文件和 `quant-session:demo-*` 不能作为生产契约。

## 7. Modal / Settings

所有弹窗复用 `ModalShell → navigation + main(content + actions)`，`#modalBody` 不再散落独立拼接的设置项。

| 分区 | 内容 / 行为 |
|---|---|
| 阅读与界面 | 正文字号、过程极简 / 详细、终端外观说明 |
| 模型 | 服务类型、自定义模型 ID、明确的未连接状态 |
| 数据源 | 本地合成 / AKShare / 停用选择，真实来源状态与上下文说明 |
| 运行状态 | 当前会话、状态、执行环境；可停止本地演示，结束后按钮禁用 |
| 关于 | 版本与原型环境 |
| 证据 | 可用与缺失分区，保留来源与判断边界 |
| 报告 | 摘要、版本记录与 Markdown 下载 |
| 会话设置 | 名称字段和统一操作区 |

- `Section` / `FieldRow` / `ActionButton` / `IconButton` 共享对齐、间距、描述与焦点样式。
- 桌面左导航、右内容；窄屏导航横向滚动，内容自身滚动。
- 关闭使用 Lucide；原生 dialog 提供焦点约束、Esc 关闭和触发点焦点返回。导航支持方向键、Home/End。
- 模型、数据源与阅读偏好保存在当前浏览器；不保存密钥，不发出真实模型请求。模型名即使保存也仍标未连接。


## 8. Footer

- 模型、数据源、运行状态三个字段都是按钮，分别直接打开对应设置页，避免先进入无关总览。
- 模型名前使用约 12px、奶油色 Lucide 图标；长名称截断但 tooltip 保留完整内容。
- 数据源选择同步底栏和 Overview，明确区分示例、未连接与未启用。
- 运行状态页与本轮发送 / 停止共享状态；不能显示一套独立的假状态。
- 保留低高度单行，hover/focus 时提供轻背景；装饰性标语不作为设置入口，窄屏隐藏。

## 9. 响应式与可访问性

| 宽度 / 场景 | 行为 |
|---|---|
| 1440×960 验证 | 会话 + 330px Overview；展开 Sessions 后增加约 224px 列；各面板等高 |
| ≥1600px | Overview 可扩大至 370px；正文仍限制最大宽度 |
| ≤900px | Sessions 改为抽屉，避免挤压会话 |
| ≤760px | Overview 默认隐藏，按需打开抽屉；主界面单列，输入区保留 |
| ≤600px | 设置导航横向排列，字段收紧；底栏长名称截断 |
| 390×844 验证 | 输入可访问、菜单同宽、底栏无横向溢出；触屏次要按钮可见 |

所有图标按钮需要可访问名称；保持键盘 focus-visible。原型没有引入扫屏线、闪烁光标装饰或无限动画背景；尊重 reduced-motion。真实屏幕阅读器、系统 IME 和高缩放场景尚未完成验收。


## 10. 组件与状态所有权

| 区域 | 代码 | 状态 / 数据责任 |
|---|---|---|
| 页面装配 | `components/app-shell.js`、`header.js` | `app.mjs` 先挂载再绑定控制器 |
| 会话列表 | `components/sidebar.js` | `session.js` 管理本页会话映射 |
| 对话 | `components/stream.js` | 模拟轮次、折叠、滚动、复制 |
| Overview | `components/overview.js` | `data/market.js` 合成行情，保留 metadata |
| Composer | `components/composer.js` | `composer.mjs` 交互，`composer-core.mjs` 纯编辑逻辑 |
| 弹窗 | `components/modal.js` | 唯一 dialog owner、偏好持久化 |
| 环境设置 | `components/environment-settings.js` | 模型/来源/运行分区，复用字段组件 |
| 底栏 | `components/status.js` | 派生显示、设置入口，不拥有第二份运行状态 |
| 基础控件 | `components/ui.js` | 转义、Lucide、按钮、字段行、内容分组 |

`styles/` 按区域维护，`data/` 集中示例和品牌，`tests/` 存放纯编辑/组件检查。删除旧生成脚本、历史截图、过期 CSS 和开发缓存 URL。原型不使用额外 UI 框架；生产应将这些区域映射到 #81 的 React 组件，复用 Host 状态而非搬运原型全局模拟桥接。

## 11. 验收与实施边界

| 项目 | 本轮交付 | 生产待办 |
|---|---|---|
| 布局与样式 | 可运行设计原型与截图 | React 组件迁移与现有功能回归 |
| 输入编辑 | 纯逻辑检查 + 浏览器候选交互 | 实际 IME、真实搜索、引用解析失败处理 |
| 会话 | 本页创建/切换/草稿保留 | Host 持久化、多客户端、运行隔离、订阅释放 |
| 模型与数据 | 本地偏好与明确未连接显示 | 真实模型目录、诊断、配置验证与保存冲突 |
| Overview | 合成样本 + 空状态浏览器检查；异常投影组件检查 | 真实刷新、超时、部分结果、重试与旧值策略 |
| 证据与报告 | 明确标示的合成内容和本地下载 | 按轮次绑定真实证据/版本/保存/复核/删除 |

截图为当前代码的真实浏览器渲染，但其中业务数据是合成的；不是 CLI 截图，也不是已接入 Host 的生产验证。复现记录与截图附件见 [#84](https://github.com/yangjingo/oh-my-quant/issues/84) 关联的 Draft PR。截图不进入 git；本地保存在忽略的 `output/web-ui/`，通过 `capture.cjs` 重现。附件记录 Windows、浏览器、窗口尺寸和受测版本；没有附件时，本地路径不能当成评审者可访问的证据。

## 12. 参考与后续实现顺序

- [PR #81](https://github.com/yangjingo/oh-my-quant/pull/81)：现有共享 React shell；保留其契约与结果访问能力。
- [Issue #80](https://github.com/yangjingo/oh-my-quant/issues/80)：Overview 去重、品牌、状态栏图标、阅读层次。本文应用其 Web 视觉方向，不关闭 CLI 验收。
- [Codex TUI](https://github.com/openai/codex/tree/main/codex-rs/tui/src)：连续会话与活动摘要的参考。
- [ZCode](https://github.com/zai-org/ZCode)：光标局部触发、引用身份和长输入折叠的参考。
- [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)：极简工具行、会话及输入区参考；具体功能仍以 WhyJ Host 能力为准。

建议先确认此区域规格，再在 #81 / #50 的范围迁移布局与公共控件，随后接入 Host 的真实会话、命令、引用和设置。独立验收后台运行、重连、异常恢复与 Electron；不要用静态原型通过代替这些结论。
