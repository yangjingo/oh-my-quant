# UI/UX：让研究过程可理解，也可恢复

量化界面最容易制造的错觉，是把复杂过程压成一片平滑的“正在分析”。用户看到数字不断出现，却不知道它们是缓存、当前请求还是部分失败后的残留；看见模型停止输出，也不知道研究是否已经完成。

交互设计首先要让用户辨认当前对象、状态和下一步，再追求信息密度与视觉统一。本页维护已有 TUI、旧研究宿主与共享 React 界面的交互边界；`apps/web` 已连接本机 Host，Electron 入口仍待接入。产品形态由[PRD](../prd.md)定义，视觉规范由[DESIGN](../../DESIGN.md)维护。

<a id="uiux"></a>

终端实现与专属测试/探针位于 [apps/tui](../../apps/tui/README.md)，共享 React 界面位于 [apps/web](../../apps/web/README.md)。各入口接入共享 Host 的进度分别记录，不能将浏览器结果等同于桌面验收。

## 多入口共享语义，不强求相同布局

Desktop 面向 Windows/macOS 用户，CLI/TUI 面向 Linux 专业用户。它们复用研究服务，但输入能力、屏幕空间与使用习惯不同。界面层接收用户意图、调用状态与结果，交付可操作的呈现；它不接管模型循环、行情口径或研究完成判定。

TUI 将研究、行情概览和输入组织在有限空间里，保持输入可达、长内容可滚动。底栏只保留模型、数据来源和组合等必要身份，避免把所有后台状态都塞进一行。字体与中文宽度依赖终端，因此不能仅凭某张截图推断所有环境一致。

共享 React 界面保持完整对话与固定输入区，会话列表、对话、行情概览和结果入口有独立位置；窄屏通过开关访问侧区。浏览器演示使用显式合成客户端，不能代替真实研究服务验收。

这种差异不是两套产品逻辑。任务状态与数据含义应来自共享服务，布局负责让各入口的用户看懂它们。具体组件、状态与接入边界参见 [共享 Web UI](./web-ui.md)；演示与正常入口共用组件，示例数据仅由开发适配器提供。

## 先保护输入，再考虑提交速度

CLI 的空闲 Composer 占 5 行，命令或引用候选、多行输入和排队时扩展到 8 行，并受终端高度约束；布局、滚动和命中检测使用同一计算。空输入时光标位于占位提示之前，`›` 与发送图标 `↵` 使用金色强调。顶部品牌与版本同行，Unicode 点阵标记占两列一行；运行时复用重绘节拍显示品牌动画，结束后恢复静态标记。字体需要支持 Braille 字符，真实终端字体与输入法仍须单独验收。

正文、列表、普通表格值和代码使用暖灰 `#B8B4A8`，标题和少量重点使用奶油色 `#FFF3C4`。思考正文保留低强调颜色 `#8F8A7B`、两格缩进和段落间距，移除独立的 `Thinking` 标题，保留运行进度。底栏模型名前使用单格奶油色 `◈`，不改变共享 Desktop/报告颜色。

用户仍在输入法组合阶段时，发送动作不应误触发；研究忙碌时，新输入也不应悄悄覆盖当前任务。TUI 的排队与引导由 Harness 管理，Web 忙时保留草稿，界面不擅自并发启动第二份研究。

草稿、已提交请求和已保存设置需要不同反馈。关闭面板可以取消尚未完成的检查，却不能暗示已经保存的设置被撤销。恢复失败也应保留当前工作，不能先清空页面再发现目标资源不可用。

这意味着某些操作需要等待或明确确认，但等待应说明原因。把按钮做得始终可点，却让旧响应覆盖新输入，损害的不是一个小交互，而是用户对状态归属的判断。

## 输入与引用

空输入时，光标位于输入行起点、占位提示之前；输入后跟随实际文本末尾。输入箭头 `›` 与发送/排队图标 `↵` 使用加粗金色强调（`#C99A2E`），辅助说明继续使用柔和灰色。

空输入提示为 `Ask anything · @ to reference · / for commands`，不再把 `/config`、`/artifact` 当作固定入口提示。`/` 仍打开命令建议。输入 `@` 显示带类型的本地候选；继续输入名称可筛选，↑↓ 选择，Tab 或 Enter 补全，再按 Enter 发送。文件名中的数字正常输入，不触发命令数字快捷选择。候选异步更新，旧查询结果不能覆盖新输入。

- `@file:notes.md` 或 `@notes.md` 引用相对启动目录的文件，也支持绝对路径。含空格写为 `@"file:My Notes/研究.md"`，目录候选可以逐层展开。发送时读取 UTF-8 文本快照并记录真实路径与 SHA-256；每个文件最多 128 KiB，目录、二进制、非 UTF-8 和缺失文件明确报错。
- `@session:会话ID` 引用当前工作目录下保存会话的活动分支，不切换或续接该会话。内容为最近 24 条可读消息/压缩摘要，每条最多 4000 字符；附会话路径、leaf ID、条目 ID、节选哈希、略去条数与逐条截断标识。历史回答只是上下文，不是本轮已核验事实。
- `@evidence:会话ID/结果条目ID` 引用活动分支中的一个工具结果，携带原会话、调用/结果条目 ID、调用参数、结果内容及哈希。`@evidence:` 同时列出当前会话结果与已保存会话的证据目录；选择目录继续选择结果。失败结果明确标记，其他结果仅称“已记录”，不会绕过现有研究核验、自动满足任务验收或合并分支。

一次最多 8 个引用，展开内容总计最多 256 KiB。自然语言请求和研究中的排队消息都在发送前解析；聊天展示保留原输入，持久化的模型消息保留引用快照。没有引用的请求不扫描文件。读取失败不调用模型，可按 ↑ 找回原输入修改。runtime 负责发现、读取和来源信息，TUI 只消费候选并处理键盘；文件内容作为资料发送给当前模型，slash 命令不展开 `@`。

## 渐进展示必须同时解释新旧数据

CLI Overview 顶部只保留一次 `Refresh: YYYY-MM-DD HH:mm`，表示本地刷新尝试开始时刻，不是交易日或所有报价的新鲜度保证；首次请求前为 `--`。行情行不重复来源、日期、回退详情，也不再另设 Source 区块，底栏继续显示配置来源。`~` 表示等待中的旧值，`!` 表示旧值或旧窗口，`--` 表示缺失；部分可用时移除额外的 `Partial · ! old / -- missing` 说明行，保留逐行标记与重试快捷键。原始观察的日期、来源与回退元数据仍然保留。

行情先返回几行时，可以提前展示，减少整屏等待。但本轮数据、旧缓存和未返回项不能混成没有标识的完整表格。首批结果到达前可显示明确标记的上次内容；本轮开始展示后，尚未返回的项目保持等待或缺失。

刷新失败且没有新结果时，旧值应标记陈旧；已有部分结果时，应保留其来源和日期并说明缺项。数据日期与刷新时间分别呈现，因为“刚刚更新界面”不代表“刚刚产生市场数据”。

这里牺牲了一部分视觉整齐，换来状态诚实。等待项不计入可用数，空值不写成零，也不以加载进度冒充研究完成率。Overview 的即时浏览结果不能直接替代研究所需的固定证据。

旧请求的迟到结果必须被隔离。用户切换组合或修改来源后，界面应显示当前请求的状态，而不是让最晚返回的请求决定画面。

## 结构化呈现要保留关系，而不只是装饰

表格的价值是保持对象、单位和数值对应，图表的价值是让趋势与差异可见。窄屏、截断和格式推断都不能破坏这些关系。界面只在有足够结构依据时识别表格，不把任意 JSON 自动升级成可交互控件。

研究文本、工具结果和证据面板承担不同角色。结论应能回到来源，缺项和复核提示应靠近相关结果，不能全部藏进日志。显示合并可以减少重绘，但不能因此丢掉研究事件或改变恢复依据。

错误反馈应解释当前还能做什么：保留草稿、重新检查连接、查看旧版本，或补齐数据。界面不需要把每个内部异常展示给用户，但也不能只给一个无法行动的“失败”。

## 颜色强调信息，不承担唯一判断

市场涨跌可以按用户习惯切换红绿，但风险、操作失败和缺失值的含义不能跟着翻转。金色用于品牌与重点，不表示盈利；亮色用于标题和必要强调，正文保持更柔和的阅读对比。

W3C 的颜色使用原则要求信息不能只靠颜色区分。[1] 因此涨跌方向、错误状态与缺失原因还需要符号或文字。切换配色只改变呈现，不额外获取数据；新报告固定当时选择，旧版本不重画。

这让视觉偏好与研究事实保持分离。模型偏好的渲染形状、用户选择的配色，都不能成为数据已经核验的证据。

## 可读性需要在真实状态下验证

正常结果只是一个状态。空结果、部分成功、取消、恢复、中文输入和窄屏同样决定界面是否可靠。测量也需区分请求耗时、应用发布结果与用户真正看到画面的时间；后台回调结束不代表终端已经绘制。

设计是否成立，最终要在目标入口和环境中检查。原型、合成数据与浏览器测试能支持局部判断，不能自动证明目标桌面、终端字体和输入法都已验收。交互的完成条件应与用户可观察的行为一致，而不是与内部函数是否返回一致。
