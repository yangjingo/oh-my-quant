# Quant Harness：让一次研究有明确的完成条件

通用 Agent 能调用工具、接续对话，也能生成一份像样的分析，但这些能力还没有回答量化研究的核心问题：它研究的是否仍是用户指定的对象，引用的是哪次数据，计算和解释是否一致，恢复以后还能否找回原来的依据？

Quant Harness 将这些要求装配到通用运行时上。它维护研究范围、证据与完成条件，连接数据、计算、报告和交互；模型可以探索，任务边界不能随着回答悄悄改变。平台定位见[PRD](../prd.md)，通用会话机制见[Agent Runtime](../agent-runtime/README.md)。

<a id="composition"></a>

## 研究层不重复实现运行时

宿主提供工具、模型连接、存储与生命周期；Quant 编排在其上加入研究任务、调用前约束与结果核验。数据层解释来源，计算层解释方法，报告层固定版本，界面让过程和缺项可见。研究层负责判断这些部分是否共同回答了当前问题。

这条界线避免两种重复：为量化重新写一套 Agent 循环，或把所有研究规则塞进提示词。前者增加生命周期维护成本，后者让限制只存在于模型愿意遵守的文字中。当前方案复用通用循环，把可检查的对象、窗口和证据条件放到调用边界。

代价是需要明确哪些任务能够被结构化核验。系统不能把任意开放式判断都包装成机器可验证的结论。研究完成、模型停止输出和会话空闲是不同状态，研究完成也不授予交易权限。

<a id="tasks"></a>

## 先声明问题，才能判断是否回答了问题

任务接收用户目标、市场与标的、时间范围、基准、允许能力及接受条件。它交付当前范围、尚未满足的条件和对应证据，而不是只维护一个进度百分比。当前 CLI 还将研究限制在一个活动观察组合内，不能因为底层比较服务存在就绕开入口范围。

任务需要在相关计算之前建立，否则可以先得到一个容易通过的结果，再修改目标解释为什么它正确。修订允许保留仍符合条件的同任务证据，却不能为了显示完成而删除用户限制。范围变化必须成为明确的新决定。

调用前核对实际工具及其对象、日期、基准与任务是否一致。宿主允许的能力与任务允许的能力取交集，任务不能自动启用扩展或扩大账户权限。文字备注有助于解释意图，却不是能够执行任意规则的策略语言。

这里仍有一个重要限制：把自然语言写成完整任务，不等于理解了用户意图。任务界面应让人检查范围与接受条件；机器核验只对已经表达出来、且实现支持的条件负责。

<a id="research-state"></a>

## 研究状态从证据重建，不从总结推断

模型摘要适合减少上下文，却可能丢掉参数、单位或限定语。因此研究状态从当前会话分支的原始调用、结果和固定数据版本重建，摘要不能新增指标，也不能使别的分支结论自动生效。

状态至少要区分未返回、执行失败、未核验和已核验。缺档案与工具报错不同，管理操作成功也不一定产生量化发现。核验要求原参数、实际计算区间与固定输入一致；不能把整份归档的日期范围当作本次计算窗口。

例如，任务要求某一截止时点的动量，后来用更新数据算出的同名指标，即使数值合理，也不能替代原任务的结果。同一对象的多个判据如果使用了不同观察版本，研究层需要识别这种不一致，而不是把几个绿色状态相加。

研究投影只保留当前任务必要证据及有界的近期上下文，并标出省略。完整记录仍在会话与归档中，不再维护一份可独立漂移的研究状态文件。这个取舍减少同步问题，但恢复时必须重新检查依赖，不能把缓存的完成状态当成永久事实。

来源、处理过程与结果之间的联系，也是 W3C PROV 讨论的核心问题。本项目借此解释证据关系，没有实现或宣称兼容整套 PROV 标准。[1]

<a id="recovery"></a>

## 重试应解决原问题，恢复应保护当前工作

后续成功不能自动覆盖此前失败。重试需要与原调用的参数、任务和数据资格对应，才能说明那个未解决问题得到处理。换了标的或日期算出成功结果，只是另一项研究。

恢复也不是把保存的文字重新显示出来。系统先准备目标分支、固定报告和所需资源，核对成功后再切换活动状态；准备失败应保留当前工作。原数据丢失时，相关结论回到未核验，不能用最新缓存修补历史。取消恢复准备也不等于撤销此前已经保存的用户请求。

需要报告的任务，还必须保证报告覆盖当前修订和最终接受的结果。计算之前生成的报告不能因为标题相同就满足交付要求。报告版本、研究核验与会话切换分别拥有责任，避免一个“恢复成功”同时承诺三件没有发生的事。

<a id="images"></a>

## 图像输入扩大理解方式，不扩大证据等级

用户显式提供的市场图表可以进入支持图像的模型请求，但图片上的估计价位或趋势不等于从原始价格重算的指标。图像解析应保留观察与推断的区别，不能让视觉上的确定感替代数据依据。

当前附件按请求生命周期保留像素，结束后释放；会话只保留有限元数据，下一次请求或恢复需要重新附图。图像会发送给所选模型，生成分析仍按会话规则保存。这种设计减少长期保留原始图像，却牺牲了无需重新附图的恢复便利。账户截图缺少独立私有输入契约，不能按普通市场图表自动接纳。

<a id="verification"></a>

## 完成状态只在声明范围内成立

确定性核验能够检查固定输入、计算和拒绝条件，不能认证上游金融事实或任意语言解释。结构化任务越清楚，自动完成条件越可靠；任务越开放，越需要保留人工判断与未知。

因此，Harness 的价值不在于让所有研究都自动变成完成，而在于明确指出：哪些部分已经成立、哪里缺证据、下一次继续应从何处开始。新入口应复用这些边界，而不是把状态重新压成一个不透明的成功标记。
