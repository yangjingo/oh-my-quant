# 工作区 Host：发现、所有权与退出

Host 负责持有一个工作区的执行服务，入口负责连接与展示。`src/app/bootstrap.ts` 先发现并认证现有实例，只有不存在存活或无法确认的所有者时才启动 Bun 子进程。运行、报告与会话操作继续使用[无界面服务](./services.md)，没有另建 Agent 循环或持久化会话库。

本页描述 #75 工作分支中的实现。它临时依赖 #114，最终集成目标是 main；不能把分支测试当作已发布能力。#51 的[契约 PR](https://github.com/yangjingo/oh-my-quant/pull/107)仍需审阅与集成，CLI/TUI、Electron 入口接入分别属于 #76、#47。

## 一个工作区只产生一个执行所有者

工作区沿用 `OHQUANT_DIR`，未指定时使用当前目录的 `.ohquant`。bootstrap 复用服务的真实路径身份算法，消除目录链接与文件系统大小写别名；选择工作区不会修改父进程的环境，也不复制设置、凭证或历史。

storage 管理私有 `.host/`：短期启动锁串行化发现至就绪，执行锁由 Host 持有至停止。锁先在同目录准备含唯一实例记录的目录，再以原子重命名发布，避免暴露可被误抢的空锁。记录包含 schema、随机 instanceId、PID 和启动时间。文件时间戳与心跳超时都不能证明原进程已死：只有系统明确报告 PID 不存在才回收；存活、权限不足或其他未知状态均拒绝第二个写入者。PID 被其他进程复用时会保守阻塞，不按名称结束它。

失效回收只删除已核验旧实例的唯一记录，再尝试删除空目录。新所有者总是以非空目录出现，因此迟到的回收者不能删除替换实例。损坏、未知版本、链接或意外内容保留并报错；不通过递归删除修复锁。旧版 `.workbench-host.lock` 没有进程身份，需先确认旧 Host 已停，再人工处理，不能按过期时间自动迁移。

就绪登记包含 workspaceId、instanceId、loopback URL、协议版本、服务契约版本、应用版本以及本机连接能力。登记使用 storage 原子提交，文件权限请求为 0600、目录为 0700；Windows 仍依赖工作区继承的账户 ACL，不把 HTTP 视作同账户恶意程序的隔离。登记不是公开状态或备份分享内容。

## 启动与复用是经过认证的握手

1. 持启动锁重新读取登记，核对执行所有者。存活实例必须同时匹配工作区、协议版本与服务契约版本；应用版本只作诊断。
2. 用登记中的能力认证 `/api/host/ready`，再核对返回的 instanceId 和地址。端口开放、连接超时或看起来相近的版本不能替代这一步。
3. 新 Host 先检查已构建静态资源、取得执行锁、恢复服务读取能力并监听 `127.0.0.1`，随后发布就绪登记。初始就绪预算为 15 秒，可在调用中设置更短测试预算。
4. 子进程与入口终端分离。启动失败只终止本次启动且尚未发布就绪的进程句柄；已经发布或复用的实例不因启动端观察失败被杀死。无法确认时返回诊断，保留现场。

Bun HTTP/SSE 运行于独立 Bun 进程。Node/Electron 调用 bootstrap 时必须显式提供 Bun 可执行文件；不能把 Bun server 导入 Electron Node 并假定兼容。当前是源码开发入口，正式 CLI 与安装包运行时路径仍由后续入口工作交付。

Windows 的 Bun Shell 会把额外管道句柄传给后代，仅设置 detached/ignore 仍可能让外层命令等不到 EOF。Windows/Bun 启动因此使用隐藏 PowerShell broker 的 `Start-Process`，保留真实子进程句柄至就绪，再释放；超时指令只终止该句柄。控制通道意外关闭不视为停止授权，Host 自身另有 15 秒初始化上限。验证同时覆盖实际 `bun run web:host` 的进程退出、输出结束与后端存活，不能只测直接运行脚本。

## 连接能力与观察

Host 拒绝错误 Host、外站 Fetch Metadata、非同源 Origin、无效 token 与未声明方法。页面同源 bootstrap 返回普通连接能力；业务 RPC、状态读取和 SSE 通过请求头使用它。连接 token 不放在 URL、普通事件或日志里，原始数据路径与模型凭证不进入协议。

后端停止另需私有控制能力，浏览器 bootstrap 不返回它。停止请求还必须匹配 instanceId，旧实例的控制请求不能停止重启后的 Host。登记损坏、协议不兼容、活进程无法连接时都不启动替代实例。

SSE 的 ready 和快照信封带 instanceId；revision 仍归会话服务。同一实例内比较修订，实例变化时入口必须重取身份与快照。保留全量快照与现有合并/背压，不把本轮扩展为增量事件协议。历史列表和初始握手的大小有回归测量，完整快照随选中会话内容增长。

`attachWorkspaceHost` 为 TUI/Desktop 等入口登记临时客户端身份，调用方须在 90 秒内续期，建议每 30 秒续期，离开时显式 detach。过期只移除 presence，不取消运行。现有 Web SSE 连接本身也计入观察者；空闲停止同时检查客户端登记、观察连接、在途操作与活动 run。

## 退出语义

| 动作 | 行为 |
| --- | --- |
| 关闭 Web、取消 SSE、detach 客户端 | 释放观察，运行继续，Host 继续存活 |
| 取消研究 | 既有服务按完整 workspace/session/run 身份取消，Host 不退出 |
| 入口请求空闲停止 | 仅本次启动的实例可请求；存在其他登记、观察者、在途操作或活动 run 时拒绝 |
| 显式停止后端 | 持控制能力并指定 instanceId；拒绝新操作，关闭观察，取消并等待已有服务收尾，然后移除本实例登记、释放执行锁 |
| 停止收尾超时 | 子进程最多等待 10 秒后退出；残留登记/锁由下一次发现核实进程死亡后回收 |
| 崩溃或机器退出 | 连接断开；checkpoint 仍按已有规则投影 interrupted，不自动提交或重放 |

旧单股 `workspace:dev` 前台入口也取得同一执行锁；它不冒充兼容的通用 Host。直接服务消费者及 CLI 迁移由 #76 接入所有权边界，桌面关窗、托盘与完整退出由 #47 接入；本页不声称这些入口已经迁移。

## 开发与验证边界

`bun run web:start` 构建 React 后启动或复用工作区 Host，打印地址并返回；`bun run web:host` 仅使用现有构建产物。浏览器关闭、启动终端退出不会停止服务。`bun run host:stop` 明确请求停止选中工作区后端，包括其活动研究。独立 `web:dev` 的 Vite 页面仍为未连接界面，不隐式打开开发跨域或暴露凭证。

并发进程锁、就绪失败、失效登记、鉴权、客户端 detach 和退出由 `src/app/host/test/` 验证；既有服务测试保留真实 Host kill/restart、精确取消与 SSE 接回。测试使用隔离工作区和确定性模型，不能证明真实行情完整性、模型质量、安装包接入或目标机器验收。完整恢复资格、未知工具副作用对账和长期资源预算仍由 #77 负责。
