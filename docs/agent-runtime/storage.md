# 存储：区分可以重取的数据与不能重写的历史

本地文件并不都属于缓存。行情可以重新获取，用户选择不能靠默认值重建，旧报告也不能用今天的模板和价格替代。存储层先划分这些责任，再决定怎样写入、恢复和清理。

Storage 接收带身份和版本的内容，交付已提交的记录、固定引用或明确失败；Source 解释数据来源，Runtime 绑定设置和存储，Agent 管理会话生命周期。UI 不自行拼接路径或修改文件。这样，换一个入口不会同时改变持久化规则。

## 四类数据，对应不同的保留责任

设置、凭证引用和观察组合是用户维护的持久状态。公开行情的最新快照可以用于缓存；被研究引用的行情版本则必须保留。会话、比较、回测和报告属于显式成果，不能因超过缓存期限而自动删除。私有账户与订单有独立宿主和存储边界，不混入公开行情、默认研究上下文或分享副本。

观察组合只保存标的与分组，不等于账户持仓。旧 `.ohquant/portfolio/` 文件是遗留用户数据，只在用户主动迁移时读取，不形成持续依赖，也不自动删除。具体文件入口见 [Storage 模块](../../src/storage/README.md)，本页维护保留与提交语义。

这种分类增加了磁盘占用，也意味着“清缓存”不能解决全部空间问题。人工删除研究归档后，旧引用可以失效，但系统不能静默换成新数据以维持绿色状态。

## 写入成功必须对应明确的提交点

工作区 `.host/` 是私有进程登记与所有权元数据，包含本机连接能力，不属于行情缓存或会话 journal。启动锁与执行锁只在确认旧进程死亡后回收，不能按 mtime 抢占；损坏或未知格式保留。就绪登记经原子替换发布，正常停止仅移除匹配的本实例登记。机制与权限边界见[工作区 Host](./host.md)。

设置与观察组合采用版本检查：草稿绑定读取时的文件版本，写入时在锁内重新比较。另一窗口已经保存时，旧草稿应报告冲突并保留编辑内容，而不是覆盖新值。损坏文件也不能被当成空配置重新保存。

锁协调写入者，原子替换让读者看到完整版本，两者不能互相替代。默认实现先写唯一临时文件，再同步并替换目标；失败不提前发布成功状态。Windows 的短暂文件占用只允许有限重试，不先删除原文件，也不无限阻塞界面。长时间网络操作不放在短同步写锁里。

设置提交与连接验证也必须分开。并发冲突需要重新读取；临时占用可以重试；格式损坏需要修复或恢复。把这些情况统一成“重试保存”，容易把可恢复冲突变成数据覆盖。

## 最新缓存与研究版本回答不同问题

最新快照同时提交数值、来源、时间与响应成员。新鲜度既看抓取时间，也看请求覆盖；积累了更早价格，不代表最近响应包含这些日期。普通研究复用与陈旧回退都受最近成功响应的日期集合约束，不能用旧行补出貌似完整的新响应。

同日期修订可以替换缓存值，但旧研究版本不随之改写。前复权历史可能整体变化，因此当前响应不能与旧尺度直接拼接；未知价格口径和缺失成交额也不能被补成确定值。来源解释见[数据契约](../quant-harness/source-data-providers.md)。

研究引用绑定实际输入与不可变版本。历史截止查询只接受已经提交、且在截止前观察到的响应；它证明应用保存过什么，不证明供应商当时首次发布了什么，也不消除存活偏差。

归档文件存在还不够。进程可能在写出版本后、提交最新快照前退出，因此 Bars 通过有效 head 或内容绑定的提交标记识别已提交修订；基金 NAV 以提交标记完成为准。未提交的孤立文件不参与恢复。旧格式无法补出过去没有记录的提交证据，兼容读取须保留这个限制。

## 会话保存事实，研究状态按事实重建

会话 journal 保存分支、用户输入和工具结果。完整分支复制、摘要与 leaf 移动按各自提交边界完成；失败不先切换内存状态。重复身份、缺父节点或截断记录不能被部分接受，列表可以隐藏坏记录，但保留原文件。

研究完成状态从当前分支及固定输入重新投影，不另存一份会漂移的真值。归档后来丢失时，核验状态可以退回未知，但不能删除已经发生的事件。摘要减少模型上下文，不取得修改研究事实的权力。

默认会话提交会复制整份文件，成本随历史增长。离线列表的上下文估算与活动模型窗口也可能不同；它们服务导航和预算提示，不是精确恢复承诺。会话机制与取消边界见[运行时](./README.md#pi-integration)。

## Workbench 检查点与模型上下文分工

`.ohquant/workbench/sessions/` 保存版本化的界面投影、稳定身份与原 Quant journal 引用。列表分块读取有界首行，选中后验证完整摘要和身份；替换复用文件锁、存储 revision 与原子写入。未知版本、损坏或过时写入保留原文件，其他会话仍可访问。这些私有检查点不是不可变报告或工具副作用账本。

重启读取不改写旧记录、不发送请求；遗留 running 投影为 interrupted，已开始但没有保存结果的工具保留为待核对。浏览器草稿只属于视图，不能作为运行真值。格式、兼容性与确认规则见[会话连续性](../quant-harness/workbench-sessions.md)。原 settings、Quant journal 与成果格式不变；新格式没有自动历史导入。

## 报告固定字节，恢复核对来源

报告保存完整快照、元数据和来源关系。新版本追加归档并更新 head，历史列表沿已提交版本链读取；崩溃留下的候选不应显示成完成版本。HTML 浏览视图缺失时，可从同一已核验快照修复，不能重新运行生成器冒充原页面。

恢复允许会话继续追加，但要求原先引用的记录、顺序和分支关系仍然成立。来源损坏时保留报告与当前工作，明确说明无法恢复。列表不可见、移除当前入口和删除不可变归档是不同动作，不能让清理列表顺带抹去研究证据。

完整报告可能含用户原文、组合名称和模拟金额。分享使用独立白名单投影，预览与下载读取同一份版本字节，操作本身不上传。公开投影由[制品设计](../quant-harness/artifacts-design.md)维护，存储保证选中的版本没有被换掉。内容哈希可以发现字节变化，不能认证供应商事实或模型解释。

## 凭证与私有状态不能靠目录名获得保护

设置可能保存明文数据凭证，独立模型登录文件也可能包含 OAuth token。显示脱敏不等于加密；文件权限、备份和对外传输由宿主负责，这些文件不进入公开缓存、报告分享或自动清理。

显式链接 Pi 账号时，WhyJ 保存账号与路径引用；后续令牌轮换在 Pi 文件锁下进行，保留其他账号和权限。退出链接只移除 WhyJ 指针，不删除 Pi 的账号。独立登录与外部链接必须保持不同的所有权语义。

持久化保证最终仍受文件系统约束。现有回归覆盖冲突、取消、损坏和进程终止，不能据此承诺所有设备的断电安全。新用途应先确定所有者、提交点、失败后保留什么、谁有权删除，再选择文件格式。
