# 扩展宿主：替换能力，不复制应用状态

扩展机制的价值不只是多注册几个工具。真正困难的是能力变化时，在途研究仍然知道自己使用的是哪份资源，失败的更新不会破坏原有会话，禁用之后也不会继续悄悄调用旧工具。

WhyJ Extension API 1 将资源声明、生命周期和会话接线分开。它使用 Pi 的工具与技能数据类型，但不是 Pi Coding Agent ExtensionAPI，不承诺任意 npm Pi 插件可以直接运行。社区 Skills/MCP 的安装与连接由 [Community Tools](../quant-harness/community-tools.md)维护，两者不共用一套兼容性承诺。

## 声明资源与运行资源必须一致

扩展接收工作目录、生命周期取消信号和诊断出口，交付声明过的工具、技能、命令及可选 capability。宿主核对 API 版本、资源名称和声明与实现的一致性，再决定是否发布。

名称冲突须在激活前解决，包括扩展之间及基础宿主已经预留的名称。否则两个实现可能以同一个名字进入模型请求，用户无法判断调用属于谁。没有声明能力不能解释为自动拥有全部权限。

当前扩展通过显式静态 import 加入应用 catalog，不扫描或执行任意目录。重载重新初始化当前构建中的定义，不从磁盘热导入新代码；源码升级仍需重新构建和启动。这个选择限制了安装便利，但让加载来源保持明确。

## 更新先准备，成功后再替换

加载或重载先准备候选资源，通过校验才发布。失败保留原有可用实例，并清理候选已经创建的资源；不能先清空工具，再发现新版本无法启动。

禁用进入串行执行阶段后撤销调用入口，取消在途工作并等待协作退出；重载则在新实例发布后退休旧实例。迟到初始化结果也需要清理，清理错误进入诊断，不能让其他扩展一起消失。

这里的取消是合作协议。受信任的同进程 Node 代码若忽略信号或阻塞事件循环，宿主不能强制隔离它。因此生命周期管理不是恶意代码沙箱，也不是强制终止保证。运行不可信实现需要另行设计进程与权限边界。

## 请求快照保护一轮研究的含义

会话在独立请求的空闲边界读取一致的工具、技能、能力和版本快照。在途模型循环保留原注册快照，但已禁用的旧资源调用会明确失败，不能继续执行被撤销的能力。

准备新会话资源需要整体成功。若扩展技能与本地技能冲突，刷新失败并保留旧资源，修正后再重试。新增工具不清空历史，也不要求重建会话；只刷新技能不冒充工具集合变化。

恢复时，显式保存的工具选择与当前允许集合取交集，显式空集合仍为空。自动选择模式可以接纳新增工具；两种语义不同，不能为了让恢复成功而自动扩大权限。

代价是启用资源并不立刻改变在途研究。界面应说明变更何时生效，而不是用即时切换破坏请求的可解释性。一般的快照与队列规则见[运行时](./README.md#dependencies)。

## 应用管理与扩展运行各自持有状态

默认 AppRuntime 启动时加载静态 catalog 和持久化禁用选择，再组装会话。内置 `whyj.core` 复用工具注册表，不复制计算、数据或存储实现。扩展宿主提供完整资源集合，独立宿主要显式装配所需基础能力。

管理入口复用配置命令。只读查看可在研究进行时使用；启用、禁用和重载要求空闲，语法由应用帮助维护。更改先完成宿主操作，再按设置版本保存选择；保存失败尝试恢复原启停状态并报告错误，不能显示已持久化成功。

未知 ID 保留为不可用项，避免升级把用户选择悄悄删掉。其他运行进程需要重启读取新选择。单次 CLI 管理使用临时宿主并在返回前清理，不为查看列表创建模型会话。列表成功也不代表每个扩展初始化成功。

禁用核心扩展会移除后续模型请求中的相关工具，基础任务和本地管理入口仍可用。Overview、Doctor 与配置服务拥有自己的生命周期，不因 Agent 工具禁用而全部停止；禁用的研究能力也不能通过 shell 自动绕过。

## 能力声明不等于研究证据

capability 描述宿主已知的能力条件及依赖工具，可以表达可用、缺失、未核验或需要输入。宿主复制并校验回执，拒绝未知工具绑定与名称冲突，调用方后续修改对象不会改变已发布快照。

它不自动注册工具，也不能仅凭作者声明把结果变成可信证据。默认宿主不再据此维护逐技能资格系统；可选准备策略由自定义宿主管理，研究任务仍按自己的范围和核验规则接纳结果。

这种分工避免每个插件重新定义研究成功。插件负责资源及生命周期，宿主负责启停与可见性，研究层负责输入和结果是否回答了当前问题。扩展成功执行只完成了其中一层。

## 如何判断接入成立

校验关注不兼容版本、冲突名称和声明不符；宿主回归关注失败更新、取消和清理；会话接线关注真实 Pi 循环中的资源增删、任务范围及原会话保留。应用管理还要验证设置冲突后的状态与退出清理。

现有本地 fixture 与模拟服务可以检查这些边界，不能证明第三方服务可用、任意插件安全或独立发行包已经兼容。公共契约和接入示例留在源码，本页不复制另一套接口清单。
