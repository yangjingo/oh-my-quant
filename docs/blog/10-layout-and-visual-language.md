# 10｜80×24 的屏幕里，什么值得一直留下？

Agent Engineering / oh-my-quant · 初稿 2026-10-13 · 修订 2026-10-13 · UI 布局与视觉语义

研究终端希望同时展示回答、行情、来源、模型状态和输入。每一项都有道理，但它们不能同时拥有最高优先级。窗口变小时，布局必须替产品作出选择。

## 每多留一行，就少读一行什么？

Analyzing 是主要工作区域，Overview 提供市场背景，Composer 保留输入，底部状态帮助用户判断当前连接。固定位置能形成稳定的操作预期，但固定区域越多，真正可阅读的研究内容就越少。

这不是把字号缩小就能解决的问题。终端按字符单元格布局，字体与真实字号由用户的终端控制。[DESIGN](../../DESIGN.md)中的字体、像素间距和圆角可以作为品牌与 Web 产物的参考，不能把 `16px` 正文或圆角卡片照搬成 TUI 已经实现的能力。

因此，终端里的留白需要换一种语言：少占几行装饰，给字段和操作分配稳定区域，让长中文按实际显示宽度换行。它首先是一份空间预算，然后才是视觉风格。

## 稀疏的画面，也可能只是高度算错了

2026-09-15 的小屏审计发现，60×20 中带完整预览的会话列表只能看到两行，报告列表只能看到四行。原因不是内容太多，而是从已扣过顶部区域的 `contentH` 中再次扣除了元信息高度。界面看起来不拥挤，却浪费了本来可以用于阅读的位置。

同一次复核还发现，空报告列表把整句下一步指引放在单行页脚，窄屏只剩前半句。这个“简洁”让用户失去了行动信息。Settings 没有常驻操作提示，进入编辑后还需要凭经验猜测怎样保存或退出。这些问题对应的[小屏回归](../../src/tui/test/panel-small-screen.test.ts)继续留在代码中。

这些反例使“Whitespace first”不能被解释为尽量空。需要保留的是能帮助用户理解分组和层级的空白，而不是由重复扣高、无效装饰或截断造成的空白。

## 先分配注意力，再分配颜色

当前主布局在宽度不足 78 列时隐藏 Overview，研究区域扩展；用户也可以在设置中主动关闭它。这里接受了一个损失：小屏不再持续显示旁侧行情。换来的是研究和输入保持可用，而不是两块区域都缩到难以阅读。78 列是当前实现阈值，不是对所有终端都最优的结论。

面板也按信息职责分配区域：空态指引进入可换行正文，页脚保留数量或状态；列表按真实起点到底边计算容量；Settings 为字段、草稿、操作和错误各自留位。错误出现后仍能看到所改字段和输入，而不是让错误文本挤掉操作对象。

视觉语义采用相似的分离：

<a id="visual-language"></a>

清理时发现，旧渲染说明和存储规范还维护独立 amber / `#E8B339` cash gold，旧渲染稿又把固定红涨绿跌写成全部产物的规则；它们已经与 DESIGN 和共享 token 分叉。这不是再选一种金色的问题，而是同一种视觉信号由谁解释的问题。因此删掉并行色表，把 DESIGN 留作视觉来源，渲染文档只说明 token 怎样映射到终端和报告，存储规范则只解释旧报告为何不随设置重画。

渲染方案本身也做过一次收缩：早期草案同时设想独立 renderer 包、制品 schema、主题层和 MCP render 工具，而当时真正缺少的是让模型保留结构化行。现有 Session 注入和文本 parser 已能承接表格、sparkline 与对比块，因此先复用这条链，把行为纳入 UI/UX 契约。我们放弃的是没有当前需求支撑的子系统，不是丰富交互本身；代价是只能识别有限文本形状，任意 JSON 不会自动变成可交互图表。

| 视觉信号 | 表达什么 | 不应该被理解成什么 |
|---|---|---|
| 品牌金色与焦点 | 品牌、强调、当前操作位置 | 正收益或已经核验 |
| 行情红绿 | 显式约定下的上涨与下跌 | 命令成功或失败 |
| 结果与风险的状态色 | 对应结果、风险或操作状态 | 随市场涨跌约定一起反转 |
| 中性灰与 `--` 等文字 | 弱层级、零变化或缺失等不同状态 | 所有灰色都等于数值零 |

工作区默认红涨绿跌，也允许切换绿涨红跌，混合市场使用同一显式约定。新报告固定生成时的约定，旧版本不随设置重画；数字保留正负号，缺失仍用文字或占位表达。金色提供识别，但不承担金融判断。这些规则由共享语义 token 支撑，而不是让每张图临时选一套好看的颜色。[主题语义](../../DESIGN.md)

## 多显示几行，不等于已经更好用

相同数据下，60×20 会话列表的可见行数由 2 增至 5，报告列表由 4 增至 8。这是历史审计中的布局修复结果，不能改写为“阅读效率提升一倍”。相关回归检查不同尺寸、中文列表、错误输入保留和末项选择；字符网格投影也接受过浏览器视觉复核；本轮没有重做浏览器或物理终端检查。

截至 2026-10-09，本地布局流程与语义色范围已验收；目标终端的字形、输入法、最终像素仍是另一层检查。更没有证据表明某套颜色已经适合所有用户：保留符号是避免只靠颜色传意的约束，不等于做完了完整无障碍评估。

接下来值得观察的不是用户是否觉得画面“高级”，而是他们能否分清待取数与零涨跌，能否发现焦点，是否因隐藏 Overview 而频繁往返查看。布局优化应减少任务中的辨认和切换成本；如果只是让截图更满或更空，都还不足以支持设计结论。
